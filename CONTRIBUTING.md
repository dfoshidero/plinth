# Contributing to plinth

Thanks for helping. Bug reports, fixes, docs and new blueprints are all welcome.

## Human contributions only

Every contribution must be written by a person. Do not submit code, tests, documentation,
issues or review comments generated by AI tools (for example ChatGPT, Claude, Copilot,
Cursor or similar agents). Commits must not carry AI co-author trailers or "generated with"
notes; CI rejects pull requests that do.

By opening a pull request you confirm that you wrote the change yourself and have the right
to submit it under the project's [MIT license](LICENSE). Pull requests that break this rule
are closed.

## Before you start

- For anything bigger than a small fix, open an issue first so we can agree on the approach.
- Keep pull requests focused on one change.

## Development setup

```sh
uv sync
uv run pytest
uv run ruff check . && uv run ruff format --check .
```

Both must pass before a pull request is merged.

## Conventions

- Commit messages: one line, [Conventional Commits](https://www.conventionalcommits.org)
  style, e.g. `fix: reject worker ports` or `feat: add gitea ci blueprint`.
- Defaults and pinned versions belong in `plinth/config.py`, not in templates.
- Tests should check behaviour (a generated project builds, its tests pass, configs are
  validated) rather than exact file contents, so templates can change freely.
- Blueprints live in `plinth/blueprints/`. `.j2` files are rendered with Jinja; path segments
  starting with `dot-` are written with a leading `.`.

## Reporting security issues

Please don't open a public issue for security problems. Use GitHub's private vulnerability
reporting on this repository instead.
